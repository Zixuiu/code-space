🎯 场景：智能客服机器人

背景：一家电子产品公司每天收到大量用户咨询，包括产品功能、价格、售后等问题。人工客服成本高、响应慢，需要构建一个 AI 客服系统。
⚠️ 核心痛点：
  • 上下文丢失：用户问完"智能水杯有什么功能？"再问"那价格呢？"，AI 需要记得在聊的是智能水杯，而不是重新问"您说的是哪款产品？"
  • 知识静态：产品信息不断更新（价格、库存、促销），AI 不能把信息硬编码在提示词里，需要能查询实时数据
  • 对话混乱：用户可能突然切换话题，AI 需要识别意图并正确响应
✅ LangChain 解决方案：
  • 记忆 (Memory) → 用 ConversationBufferMemory 保存对话历史
  • 工具 (Tools) → 用 @tool 定义价格查询函数，让 AI 能调用
  • Agent → 让 AI 自主决定"是否需要查价格"还是"直接回答"
2

🧩 方案设计：两个版本对比

对比项 基础客服 (V1) 智能客服 (V2) ⭐ 推荐
使用组件 ConversationChain + Memory Agent + Tools + Memory
能否查价格 ❌ 只能引导用户去官网 ✅ 直接调用工具返回精确价格
扩展性 低（需改提示词） 高（加工具即可）
适用场景 简单问答、固定话术 复杂业务、多数据源
🔁 智能客服处理流程：
👤 用户提问 → 🧠 Agent 分析意图 → 🔧 需要工具？ ↗ ✅ 调用工具 → 💬 生成回答
⬆ 同时记忆上下文，支持多轮对话 ⬆

💻 核心代码实现

以下是完整的客服系统代码，包含记忆、工具和Agent三大核心组件。
# ============================================ # 第1步：安装依赖 # ============================================ # pip install langchain langchain-openai python-dotenv # ============================================ # 第2步：导入模块 # ============================================ from langchain_openai import ChatOpenAI from langchain.memory import ConversationBufferMemory from langchain.agents import create_react_agent, AgentExecutor from langchain.tools import tool from langchain import hub # ============================================ # 第3步：定义工具 —— 查询产品价格 # ============================================ @tool def get_product_price(product_name: str) -> str: """ 查询产品价格。输入产品名称，返回价格信息。 """ price_dict = { "智能水杯": "¥299", "无线耳机": "¥499", "运动手环": "¥199", "智能手表": "¥899" } for key in price_dict: if key in product_name: return f"{key} 的价格是 {price_dict[key]}" return f"抱歉，未找到 {product_name} 的价格信息" # ============================================ # 第4步：创建带记忆的智能 Agent # ============================================ def create_smart_agent(): # 初始化模型 llm = ChatOpenAI( model="gpt-3.5-turbo", temperature=0, # 0 = 更确定，适合工具调用 ) # 加载工具列表 tools = [get_product_price] # 获取 React 风格的提示词模板 prompt = hub.pull("hwchase17/react") # 创建 Agent agent = create_react_agent( llm=llm, tools=tools, prompt=prompt ) # 创建执行器（带记忆） memory = ConversationBufferMemory( memory_key="chat_history", return_messages=True ) agent_executor = AgentExecutor( agent=agent, tools=tools, memory=memory, verbose=True, # 打印思考过程，便于调试 handle_parsing_errors=True ) return agent_executor # ============================================ # 第5步：运行对话 # ============================================ if __name__ == "__main__": agent = create_smart_agent() questions = [ "你好，我想了解一下智能水杯", "它有什么特殊功能吗？", "那价格是多少呢？", "比运动手环贵多少？" ] for q in questions: print(f"\n[用户] {q}") response = agent.invoke({"input": q}) print(f"[客服] {response['output']}") print("-" * 50)

💡 代码关键点解读

  • @tool 装饰器：将普通函数变成 LangChain 工具，AI 可以主动调用
  • hub.pull()：从 LangChain Hub 拉取标准提示词模板，不用自己写
  • ConversationBufferMemory：保存对话历史，实现上下文记忆
  • handle_parsing_errors=True：即使 AI 输出格式有误，系统也能容错

🔬 组件拆解：LangChain 核心模块

这个案例用到了 LangChain 最核心的 4 个模块，每个模块解决一类特定问题：
🧠

Memory（记忆）

保存对话历史，解决"上下文丢失"问题。
示例：ConversationBufferMemory

🔧

Tools（工具）

让 AI 能调用外部函数（数据库、API、计算）。
示例：@tool 装饰器

🤖

Agent（智能体）

自主决策：分析问题 → 选择工具 → 生成回答。
示例：create_react_agent

⛓️

Chain（链）

将多个步骤串联成工作流。
示例：AgentExecutor 执行链

📌 它们如何配合？
用户提问 → Agent（分析意图）→ 需要数据？→ Tools（查价格）→ Memory（保存上下文）→ Agent（生成回答）→ 返回用户

🚀 进阶优化方向

以上是 MVP（最小可行产品），实际生产环境可以进一步优化：
数据

📊 接入真实数据库

用 SQLDatabaseToolkit 连接 MySQL/PostgreSQL，让 AI 直接查询产品表、订单表。

检索

📚 RAG + 知识库

将产品文档存入向量数据库（Chroma/Pinecone），用 RetrievalQA 让 AI 检索回答。

性能

⚡ 流式输出

开启 streaming=True，让回答逐字输出，提升用户体验。

生产

🔒 安全与审计

用 CallbackManager 记录所有对话和工具调用，用于监控和调试。

📌 完整生产级架构建议：
用户 → API Gateway → LangServe (部署 Agent) → 调用 OpenAI API → 返回结果
中间层：Redis 缓存 + 向量数据库 (RAG) + 日志系统 (LangSmith)
