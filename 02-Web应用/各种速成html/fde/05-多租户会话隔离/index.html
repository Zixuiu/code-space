FDE 速成知识点 · 实战向

Demo 能跑 ≠ 敢给客户用。每个客户/用户必须各有独立会话记忆，否则 A 的客户看到 B 的对话就是事故。这是接入任何系统的硬门槛。

你会学到

  • 为什么全局一份 Memory 会串台
  • 用 user_id 分桶管理会话
  • 内存字典 vs Redis 持久化
  • 会话过期与清理

核心概念

串台是事故：当前 langchain_server.py 是全局一份 history，多用户共用会互相看到对话。

分桶：以 user_id（微信 openid / CRM customer_id）为 key 隔离各自的 history 与 memory。

持久化：内存字典重启即丢，生产用 Redis 存会话，并设置 TTL 过期。

案例可直接参考的代码

SESSIONS = {}  # user_id -> 各自的历史

def get_session(uid):
    if uid not in SESSIONS:
        SESSIONS[uid] = {"history": [{"role": "system", "content": SYSTEM_PROMPT}]}
    return SESSIONS[uid]

def chat(uid, msg):
    s = get_session(uid)
    s["history"].append({"role": "user", "content": msg})
    reply = call_llm(s["history"])          # 调你的大模型
    s["history"].append({"role": "assistant", "content": reply})
    return reply

# 调用示例：chat("openid_abc", "智能水杯多少钱？")

动手练习

把 SESSIONS 换成 Redis（redis-py），设 30 分钟 TTL，模拟两个用户互不影响。
