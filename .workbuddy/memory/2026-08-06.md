## PC-action：修复 F1+F2 在设置快捷键弹窗"录不进去"
- 现象：任意两键组合（c+2、1+2）能录，但 F1+F2 录不进设置快捷键弹窗。
- 根因：F1 是 Windows 系统"帮助"保留键，弹窗打开时按 F1 系统会抢焦点/弹帮助，导致后续键录不进；代码捕获层（F1-F12 已支持）与 keyboard 注册层（`add_hotkey("f1+f2")`）均无限制。已排除 `_key_logger` 全局钩子吞键（其回调不返回 False，不抑制事件）。
- 修复：在 `app.py` 的 `set_shortcut` 与 `set_folder_shortcut_in_tab` 两处录入弹窗里，安装 eventFilter 拦截 `QEvent.Help`（F1 系统帮助）并 accept，避免系统抢焦点；同时 `dialog.activateWindow()` 确保焦点。macOS 版（app_macos.py）F1 非系统帮助键，未改动。
- 触发阶段仍需注意：keyboard 库对功能键组合需以管理员身份运行才稳（项目注释已说明）。
- `app.py` `py_compile` 通过。

## PC-action：回放"乱点"诊断与修复（查看boss情况流程）
- 现象：按 alt+1 触发"查看boss情况"回放，点击位置错乱（步骤1匹配到 (337,76)，而录制正确坐标是 (736,0)，差~400px）。
- 澄清：alt+1 触发键不影响回放位置——回放是纯图片匹配定位，触发键只负责"开始跑"。
- 根因：recording.json 步骤1模板 `操作1.png` 是 25×41 超小图标（蓝底白字"B"），模板特征极弱；回放对小图标用纯形状匹配（confidence=0.8、颜色匹配=关），任务栏/标题栏到处是相似小图标，极易误命中到其它同名图标。roi_hint（录制坐标）仅在录制点周围 300px 切片内找"得分≥0.8"，顶部条里任意相似图标即可达标返回。
- 关键线索：操作1.png 与 recording.json 时间戳为今天 10:32（刚重截/编辑过），操作2.png 仍是 8/4 旧图；新图尺寸(27×50)与 json 记录(25×41)对不上，疑似重截时截错目标。
- 修复：在 `image_recognition.py` 的 `replay_coordinate_operations` 小图标分支，强制开启颜色匹配 + 置信度 0.8→0.9，降低误命中（不可治本）。治本需用户重截一张更大、带周围背景/文字的 `操作1.png`，使形状唯一。
- `image_recognition.py` `py_compile` 通过。
